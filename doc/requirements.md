# 《Rooftop Apartment》需求文档

## 1. Overview

《Rooftop Apartment》是一款有状态 AI 驱动的竖屏多人关系模拟：玩家以自己的 AlterU 身份加入一间屋顶合租公寓，在房租、公共秩序和邻里声誉之间处理生活冲突。单次游玩目标为 8–12 分钟，故事不按固定轮数结束，可跨日、跨设备恢复。

核心情绪承诺：小事不会立即结束，但每句话都会改变住户下一次是否愿意相信你。

主界面只有按时间推进的对话/事件流、底部快速回复与自由输入，以及收纳住户、房间、公共柜和留言簿的 World 抽屉。支持完整 zh/en 内容；明确换语言回答时，后续界面与回复自动跟随，历史记录不重写。

当前 AlterU 用户是故事主角。玩家行动与住户页显示其用户名和头像；关键剧情生图可引用公开 HTTPS `head_url`，但头像资料不写入故事存档。

## 2. Visual Design

视觉方向为“屋顶生活记录簿”：夜瓦、信纸、植物绿、砖红和窗灯黄组成克制的合租生活档案。顶部显示标题、地点/时间、租金压力、公共秩序、邻里声誉、`Aa` 文字设置与 World 按钮；中部为独立滚动时间线；底部 104–152 px 为快速回复和自由输入。`Aa` 提供小/标准/大三档，默认标准正文 17 px，大档 19 px，并在下次打开时保留。

玩家消息位于右侧并配 32×32 px 头像，住户消息位于左侧；叙述、检定、数值变化与留言簿记录拥有不同结构。场景图只在新房间、关系转折、证据发现、关键协商或章节摘要触发，并原位插入对应回复。未出图时使用公寓世界母图。

正式海报为 1024×1024 raster key art，只允许英文标题 `ROOFTOP APARTMENT`，标题位于上方 25% 安全区。完整视觉系统见 `doc/visual.md`。

## 3. Game Mechanics

### 3.1 共同生活状态

- 租金压力：初始 42，范围 0–100；补缴、损坏和延期增加 6–20，证据、分摊或谈判减少 5–18。70 以上触发催缴事件，90 以上出现搬离风险。
- 公共秩序：初始 68，范围 0–100；清晰分工和记录增加 4–12，隐瞒、失约和冲突减少 5–15。40 以下普通协作 DC 增加 2，20 以下触发公共空间失灵事件。
- 邻里声誉：初始 55，范围 0–100；互助和坦诚增加 4–10，噪音、推责和公开争执减少 5–14。35 以下房东/邻居交涉 DC 增加 2，15 以下触发投诉或驱离风险。
- 每轮状态变化来自结构化命令并夹紧到声明范围；变化必须在时间线中紧邻原因显示。

### 3.2 住户、关系与检定

- 固定住户为 Jo、Lin Cheng、Mo He；每人拥有体力 0–10、压力 0–10，以及倾听、协调、掩饰、行动力中的 0–5 技能。
- 关系事件保存人物、关系轴、变化量和来源；普通生活事件单轴最多变化 8，重大承诺、背叛、承担责任或救援最多变化 20。
- 只有结果存在后果时使用 d20：`总值 = d20 + 技能 + 情境修正`，情境修正 `-3…+3`；DC 5/10/15/20 对应简单/压力常规/困难/绝境。
- 刷新不得重掷；检定结果必须在同一场景改变证据、关系、资源或下一行动。

### 3.3 场景、选择与图片

- 每个决策点提供 2–4 个意图不同的行动，自由输入上限 160 字符。
- 场景围绕生活问题推进，可包含 1–4 个节拍；关系冲突保持 1–2 个节拍并停在玩家需要表态的位置。
- 不设置“五轮结局”；只有当前矛盾形成阶段性结果时才生成摘要，然后允许继续下一天。
- 每次行动最多触发 1 张 4:3 图片；同一时间只生成一张。图片失败保留可重试占位，不阻塞对话。
- 只有 HTTPS 用户头像可作为主角 `ref_url`；默认 `U` 不发送给 img2img。

### 3.4 连续存档

- 本游戏使用独立 UUID 和独立本地命名空间，只保存 Rooftop Apartment 世界，不与模板或其他游戏共享。
- 保存地点、日期/时间、目标、三项公共状态、剧情块、选择、房间、公共物品、关系、最后语言和可选远程 chatId。
- 正式入口默认使用 Aigram `game-chat`，每轮携带权威状态与最近 20 个非图片剧情块；带有效 `chat_id` 时才使用实验性服务端连续世界。云端优先恢复，localStorage 兜底；只在 AI 完整响应或远程 `message_saved` 后提交。
- `story_mode=demo` 只用于三段确定性 QA 演示；内容耗尽后必须明确报错，禁止无限返回通用段落。AI/远程失败不提交行动或状态，并提供 44 px“重试这一步”。
- 玩家头像 URL、用户名和头像二进制不进入 StorySave；只保存已经生成的剧情图片 URL。

## 4. Controls

- 快速回复位于横向滚动容器并使用 `onClick`；按钮按文字长度在 148–310 px 内自适应，并在窄屏限制为 82vw，长句换行，手指滑动时不会误提交。
- 自由输入常驻底部，允许选择、粘贴与系统输入法；Enter 或 44×44 px 发送按钮提交。
- World、住户/房间/公共柜/留言簿标签、关闭和图片重试使用 `onClick`。
- 时间线上下滚动是主要阅读手势。首次进入锚定第一段背景文字；提交行动时锚定玩家行动，回复完成后锚定本轮第一段结果文字。图片占位、生成完成或失败都不能改变当前阅读位置；用户需要时可用“新内容”按钮返回底部。
- 主验收为 390×844 与 320×568；焦点可见，移动端不依赖 hover。

## 5. Win / Lose Conditions

没有固定回合胜负。阶段成功表示当前生活矛盾获得可执行共识并结算代价；阶段失败会增加租金压力、破坏公共秩序或关系，但故事通常继续。

当玩家完成 2–4 个必要事实，例如找到维修记录、确认责任、取得住户授权并完成房东沟通时，生成阶段摘要与下一目标。租金压力达到 100、公共秩序降至 0，或关键住户永久退出共同生活时进入危机结算；必须展示导致结果的事件链，并允许从新的一天建立另一条时间线，不静默回滚。

## 6. Sound Effects

- 音频全部由 Web Audio 实时合成，不请求网络、不依赖音频文件。音乐/环境/事件三条总线默认相对音量为 0.11/0.075/0.16，总输出峰值不超过 0.22；总活跃声部最多 8 个。
- 主题为 62 BPM、C3=130.81 Hz、五声音阶间隔 `0/2/4/7/9`。4 秒平滑噪声循环经 880 Hz 低通形成房间与城市底噪，并叠加 60 Hz 极低音量电气层。紧张度为租金压力 40% + 公共秩序不足 30% + 邻里声誉不足 30%，从下一拍起改变脉冲密度与后续和弦音程。
- 两个连续环境声部之外最多保留 6 个短声部，总上限为 8。行动提交使用 55 ms 带通噪声与 460→390 Hz、75 ms 三角波。
- 检定成功按根音与题材音阶生成三个 160 ms 上行音；失败为 287.8→189.7 Hz、240 ms 下降音。普通变化为 340.1→363.7 Hz、120 ms；发现/新房间使用根音、五度、八度的 420 ms 上行音。
- 图片完成使用 760→910 Hz 与 1060→1120 Hz 两层短音；阶段小结播放 700 ms 三音和弦；接口错误使用 140 ms 短下降音。
- 首次真实触控前不创建 AudioContext；顶部 44×44 px 扬声器按钮切换静音并写入 `localStorage.alteru_story_audio_muted`。静音或音频失败不阻断对话、保存与恢复。
